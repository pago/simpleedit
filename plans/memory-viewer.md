# Plan: Claude memory viewer

Working artifact — removed in the PR's last commit.

## 1. Goal / non-goals
**Goal:** From a Claude session's repo picker, open that project's Claude auto-memory directory in the normal editor + file tree (+ git log when git-backed), with health problems surfaced as Monaco markers and a count badge/list.
**Non-goals:** phone companion; snapshots / "reviewed" state; SimpleEdit-driven `git init` or commits; a `[[wiki]]` link renderer in the markdown preview; persisting memory view across restarts; live (unsaved-buffer) health re-analysis.

## 2. Design decisions

**View-root model (chosen): an ephemeral `Session.memoryView` overlay, not a `worktreePath` overwrite.**
New field `memoryView?: { memoryDir: string; exists: boolean; git: MemoryGit | null; prevViewerOpen: boolean }`. Every workspace derives `viewRoot = memoryView?.memoryDir ?? worktreePath`. Only *view* consumers read `viewRoot`, and only where safe:
- FileTree root.
- File tabs' editor root (LSP root, relative-path resolution): `TabContainer` gets a separate `memoryDir` prop and uses it **only for tabs whose path is under it**; worktree file tabs keep `worktreePath` (LSP clients are keyed `${languageId}:${rootUri}`, `lsp/client-manager.ts:136` — a wrong root would spawn a TS server at the memory dir). `ComposedPanel` keeps `worktreePath` (`TabContainer.svelte:94`; main validated its paths against the worktree).
- CommandPalette: `PaletteContext` gains `memory?: { dir; git: MemoryGit | null }`. In memory mode the **file provider** lists the memory dir via a dedicated `memory:list-files` channel (bounded readdir, skip `.git`; `fs:list-all`'s git-only behaviour for real worktrees is untouched); the **commit provider and git/tour/review action providers are skipped** (`commit-provider.ts:35`, `action-provider.ts:56-86`). `palette-engine.ts:45` switches `Promise.all` → `Promise.allSettled` so one failing provider never blanks the palette.
Everything else keeps the real `worktreePath`: agent spawn (`SessionWorkspace.svelte:179-180`), cwd-follow (`sessions.svelte.ts:1252-1269`), `recordTouch`/`touchedReposForSession` (`:626`, `:955`), MCP `show_diff`/tour, persistence.
Why on the session rather than component state: CommandPalette (`CommandPalette.svelte:18-21`) and RepoPicker live outside the workspace; `viewerOpen` was lifted to the session for the same reason (`sessions.svelte.ts:80-87`). `sessionPersistence.ts:80-95` enumerates persisted fields explicitly, so the new field is never persisted; memory-file tabs are already dropped on restore by the path filter (`sessionPersistence.ts:212-213`).
Rejected: overwriting `worktreePath` (cwd-follow/trail/agent-spawn corruption); a separate pseudo-session (duplicates tabs/terminal, loses the agent terminal the user is talking to).

**Exit / entry.** Entry: "Claude memory" item in RepoPicker, gated `activeSession.provider === 'claude'` (legacy restore → 'claude'; terminals have none). Exit: a "← Back to <branch>" button replacing the worktree button while memory is active; also any user-driven repoint — `setActiveSessionWorktree` (`sessions.svelte.ts:614`, used by RepoPicker/WorktreeList/palette worktree provider/`pickRepo`) clears `memoryView`; MCP `open_worktree` handler (`SessionWorkspace.svelte:139`) too. cwd-follow (`setWorktree`) does **not** clear it — agent movement shouldn't yank the view. `openMemoryView` records the prior `viewerOpen` in `prevViewerOpen` and `closeMemoryView` restores it — cwd-follow is gated on `viewerOpen` (`sessions.svelte.ts:1265`), so leaving it forced open would silently disable follow.

**Locating the dir.** Per the official docs (code.claude.com/docs/en/memory, "Auto memory"): "The `<project>` path is derived from the git repository, so all worktrees and subdirectories within the same repo share one auto memory directory. Outside a git repo, the project root is used instead." and `autoMemoryDirectory` (settings key, any scope; absolute or `~/`-prefixed) relocates it. Resolution in main (`claudeMemoryDir(launchDir)`), first hit wins:
1. `autoMemoryDirectory` from **user settings only** (`<configDir>/settings.json`; `~/` expanded, relative ignored). Verified in the installed CLI (2.1.294): the key is "Ignored if set in projectSettings (checked-in .claude/settings.json) for security", and local/project scopes are consulted only behind a trust gate we can't reproduce — so we read neither: a cloned repo must never be able to point SimpleEdit's editor/watcher/git at an arbitrary dir (e.g. `~/.ssh`). Policy/flag scopes and `CLAUDE_COWORK_MEMORY_PATH_OVERRIDE` are not read either (known gap: such users see the default path / empty state).
2. Otherwise, the candidate project keys, in order: if `launchDir` is in a git work tree, the main worktree root (`dirname(realpath(git rev-parse --git-common-dir))` when the common dir is a `.git` dir; bare → skip), then `rev-parse --show-toplevel`; finally `launchDir` itself. The **first candidate whose `<configDir>/projects/<key>/memory` exists** wins; if none exists, the first candidate (empty state shows that path). The docs don't pin the exact git derivation, so the existence probe makes us robust to it.
SimpleEdit's own sessions launch at the project root beside the bare repo, which is not a git work tree, so they resolve to step 2's `launchDir` — matching what's observed on disk. `<configDir>` = `CLAUDE_CONFIG_DIR ?? ~/.claude` (docs imply projects live under the config dir; also needed for E2E isolation). `CLAUDE_CODE_PROJECT_DIR_NAME` replaces the step-2 keys **only when `CLAUDE_CONFIG_DIR` is also set and the name matches `/^[A-Za-z0-9_-]{1,64}$/`** (as the CLI does). Long keys: the CLI truncates project keys above a length cap and appends a hash, which `claudeProjectDirName` (`claude-paths.ts:25-27`) doesn't; the implementer extracts the cap from the CLI and, for an over-cap key, probes `projects/` for entries starting with the truncated prefix — exactly one match → use it, else the empty state (hash algorithm unknown; documented gap). **Both env vars are read from the environment the CLI actually sees**, not main's: Claude is spawned through `$SHELL -i -l -c` (`pty.ts:197`), and a Dock-launched app only inherits PATH (`shell-path.ts`). New `claudeShellEnv()` in `shell-path.ts`: one cached `$SHELL -ilc` run printing both vars NUL-separated (5 s timeout, errors → fall back to `process.env`); precedence = the session's own launch env (if SimpleEdit injected one) > login-shell value > `process.env`. `realpathSync` failures fall back to the unresolved path. The resolved memory dir is then `realpath`'d (users symlink memory dirs; chokidar and git need the real path). Auto memory being disabled (`autoMemoryEnabled:false` / `CLAUDE_CODE_DISABLE_AUTO_MEMORY`) does not hide the entry — existing files are still worth auditing; the empty state covers "nothing there".

**Git-mode detection (main, `memory:resolve`, simple-git only).** Only if the dir exists: `revparse(['--show-toplevel'])` succeeds **and** `git.checkIgnore([memoryDir])` returns `[]` (verified: `raw(['check-ignore','-q',…])` resolves `""` for both outcomes, so it can't be used) **and** `revparse(['--verify','HEAD'])` succeeds. A repo with **no commits is treated as no-git** (`git log` rejects on an empty repo → GitLog error state); `git` is then `null`. `pathspec = relative(realpath(toplevel), realpath(memoryDir))` or `null` if equal. Git mode: GitLog targets `git.root` + pathspec; diff tabs pin `git.root` (root-relative files match `git show <rev>:<path>` and `${worktreePath}/${path}` in `DiffReview.svelte:162-171`). No git: GitLog not mounted; the health panel takes its slot.
**Memory-scoped diffs.** `DiffTab` gains `memoryScope?: { pathspec: string | null }` (presence = memory diff). It is part of the tab id (`tabIdFor`), so a scoped tab never collides with an unscoped one for the same root+commit. DiffReview with `memoryScope`: files filtered to the pathspec prefix; "Start review" / tour buttons hidden (`triggerReview(git.root, …)` would review the parent repo). Every GitLog `openDiffTab` call site forwards the scope — **including the auto-open on refresh at `GitLog.svelte:69`**, not just `:82`/`:86`.
**GitLog watch cost.** `git:watch` polls `git status --porcelain` every 3 s (`git-operations.ts:8,85`); for a `~/.claude`- or `~`-rooted repo that walks far too much. `git:watch` gains an optional pathspec passed to status (`status(['--', pathspec])`), and GitLog passes it in memory mode. The `gitWatchers` registry (`git-operations.ts:18,34`) is re-keyed by **root + pathspec** so a memory GitLog neither inherits another workspace's scope nor kills its watcher on unmount.

**Health-check algorithm** — pure `src/shared/memory-health.ts`, `analyzeMemory(files: {rel, content}[]) → MemoryHealthIssue[]`:
- Index = case-insensitive `MEMORY.md` at root. Absent → `indexPresent=false` and **skip** unindexed checks (no wall of false positives).
- Index links: every `[text](target)` on any line (not only `- ` bullets); ignore `http(s):`, `mailto:`, `#…`; strip `<>`, `#frag`, `?q`; URI-decode; strip leading `./`; try `target` then `target + '.md'`. Missing → `index-missing-file` at the link's range.
- Unindexed: only root-level `.md` files ≠ index (subfolder files count as names for link resolution but never flagged). Indexed if any index link resolves to it **or** the index contains `[[key]]` for any of its keys. Otherwise `unindexed-file` (Info, line 1).
- Wiki links: `/\[\[([^\]|#\n]+)(?:[|#][^\]]*)?\]\]/g`, skipping fenced code (```/~~~) and inline code spans. Keys normalised `trim().toLowerCase()`, strip `.md`, collapse whitespace/`_` to `-`. Known keys per file: `name:` frontmatter, basename, relative path without extension; plus `memory` (index). Unresolved → `broken-link` (Warning).
- Frontmatter: tolerant hand-rolled (style of `prompts/overrides.ts:41`): BOM/CRLF, top-level unindented `name:` only, quotes stripped; bad/missing frontmatter is not an issue.
- Limits: skip files > 1 MB, stop at 2000 files.

**Who owns health/watch (git and no-git alike).** A renderer controller, `stores/memoryView.svelte.ts` (keyed by memoryDir, refcounted), owns `memory:watch`/`memory:changed`, the health fetch, markers, `bumpFsNonce`, the palette-cache invalidation and **re-resolve**. `SessionWorkspace` activates it whenever `memoryView` is set (independent of git mode). Views over it: the header **badge** (always; click → issue-list popover) and, in no-git mode, the same issue list in the right-column slot GitLog would take. Re-resolve (`memory:resolve` again, update `memoryView.exists/git`) runs on `memory:changed` events that include `addDir`/`unlinkDir` (the watcher emits those too, with the memory dir's own `unlinkDir` meaning "gone") and on a 5 s poll while `exists=false` or `git=null` (covers dir creation, `git init`, first commit — `.git` is ignored by the watcher). `FileTree` is only mounted while `exists`; a dir deleted under it flips to the empty state via the re-resolve, and `loadRoot`'s rejection (`FileTree.svelte:27-29`) is caught.

**Leaving memory view.** `closeMemoryView` first closes memory tabs — file tabs under `memoryDir` and diff tabs with `memoryScope` — going through the existing tab-close dirty guard (if the user cancels, Back is aborted), then restores `prevViewerOpen`. Without that, `SessionWorkspace.svelte:56-58` (`if (tabs.length > 0) setViewerOpen(true)`) would immediately reopen the viewer and keep cwd-follow off, and leftover memory tabs would render with the worktree root. Memory-scoped diff tabs and memory file tabs are **never persisted** (`serializeTab`, `sessionPersistence.ts:25-31`).

**Refresh.** New `memory-watcher.ts` following `editor-watcher.ts`'s refcounted client pattern: chokidar on `memoryDir` (depth 3, ignore `.git`), 200 ms debounce, emits `memory:changed { memoryDir, dirs, structural }` on **add, unlink, change, addDir, unlinkDir** (`structural` = any addDir/unlinkDir → triggers re-resolve) (`dirs` = parent dirs of add/unlink; empty for content-only changes — a saved link fix must still re-run health). Renderer bumps `bumpFsNonce` per dir (`fsRefresh.svelte.ts`) and re-fetches health. Open editors already reload via `editor:file-changed`; GitLog keeps its `git:watch` on `git.root`.

**Empty state.** `exists=false` → "No memories yet" + the path (copyable) instead of FileTree (must not mount: `fs:list` on a missing dir throws, `FileTree.svelte:28`). While shown, renderer polls `memory:resolve` every 5 s (watching `projects/` = thousands of JSONL files).

**Security.** `memory:*` is reachable over the phone socket (`ipc-registry.ts`). `memory:health` / `memory:watch` / `memory:list-files` only accept dirs previously handed out by `memory:resolve` (a `Set` in main). Because `autoMemoryDirectory` can name anything, `resolve` refuses (→ `exists:false`, not added) a dir that is `/`, `$HOME`, the config dir itself, or an ancestor of `$HOME`. Walks are bounded (depth 3, 2000 files, 1 MB/file); watcher depth 3. Watcher clients follow `editor-watcher`'s hub keying (released on window close, `index.ts:510-511`); there is no remote-disconnect hook today, so remote clients' watches live until window close — same as editor watches (accepted). Not a new hole regardless: `fs:*` is already unrestricted (`index.ts:794-833`).

**Revealing an issue.** `consumePendingReveal` only runs in `loadFile` (`CodeEditor.svelte:114`; `editor-opener.ts:37-42` documents that re-opening the active tab never consumes it). So `editor-opener.ts` gets a registry of mounted editors by path (CodeEditor registers on mount, unregisters on destroy); `revealInEditor(path, range)` applies the reveal directly when an editor for `path` is mounted, and otherwise queues it and opens the file. Markdown files open in 'rendered' mode by default where markers are invisible, so the click first switches that file to 'hybrid' via `markdownViewStore.setFor(path, mode)`.

## 5. Risks / open questions
- **Memory key** — docs confirm git-repo keying + `autoMemoryDirectory`, but not the exact git derivation (main worktree root vs toplevel); mitigated by the existence-probed candidate list. Policy-scope / `--settings` `autoMemoryDirectory` values are not read (we can't see them); accepted.
- **Agent edits to memory in a git-tracked `~/.claude`** can fire `session:repo-touch` for that repo and add it to the RepoPicker trail — pre-existing behaviour, leave unless noisy.
- **Health refresh** only on save/disk change; dirty buffers show stale markers (live re-analysis deferred).
